## 观察到的变化

- 8 个提取文本资源中，`main.js` 与 `compiled_tailwind.css` 改变，其余 6 个字节一致。
- 新旧主包的字符串字面量值集合差异均为布局类名或 CSS 渐变：新版增加 18 处原先不存在的值，移除 10 处。没有在该边界内发现新增可见英文词条。
- 授权选择面板使用 `min-h-0` 和可伸缩容器，移除了几个固定最大高度；增加顶部、底部渐变遮罩和滚动事件处理。源码显示区域选择变化时可能触发平滑滚动；这属于静态行为推断，尚非运行观察。
- Google Cloud 项目与许可证页面增加内边距、溢出约束；计费卡片的间距和行高收紧。许可证、项目名称与原有回调字段没有因翻译而改写。

## 词库与保护边界

使用现有 Babel AST 审计方法，对两个完整主包提取 React 子节点及已知 UI 字段：各有 2,733 个去重候选、322 处动态模板，候选文本集合无增删。去掉表达式内容后，动态模板的 257 种静态片段组合也无增删。适配前固定词库命中 2,010 个候选；其余包括品牌、配置与非展示内容，不能据此计算漏译率或页面覆盖率。

静态差异没有新增可见文案，不意味着旧词库已覆盖全部页面。随后真实欢迎页检查发现两版均存在的 8 条能力卡片文案未翻译，现已加入固定词库，并仅为已确认的 `onboarding-capability-*` 区域增加 UI 识别。没有扩大为任意英文替换；新增组件回归验证相同文字在聊天内容和无关普通节点中保持原文。运行结果见 [适配验证报告](adaptation-2.23.1.md)。

新布局没有改变现有保护选择器依赖的文字标识；聊天、代码、输入值、项目名、模型名及第三方内容仍须通过运行回归确认。`renderer-localize.js` 的诊断版本改为读取构建注入的 `config.patchVersion`，缺失时明确显示 `unknown`，避免继续冒用 0.4.1。

提取工具支持显式指定输出目录：

```powershell
python tools/analysis/extract-embedded.py <language_server.exe> --output artifacts/adaptation/2.23.1/embedded
```

原默认目录保持兼容；进行版本比较时应使用独立目录，避免覆盖历史提取物。提取物、完整候选、字面量差异及片段来源保存在忽略的适配产物目录，不提交发布资源。

## 验证范围与限制

已完成离线提取、资源指纹比较、两版完整主包 AST 候选比较，以及变化区域的源码核对和 REA 分析。`--help` 和空白检查通过；本机 Python 启动器打印原安装位置提示后仍正常完成提取。

本报告不构成兼容配置放行，也不代表已经检查全部登录后页面、真实服务端返回内容、系统控件或所有许可证流程。独立 Electron 的中英文切换、动态更新、用户内容保护及完整安装恢复验证须由本次适配的运行检查另行记录；不能把旧版组件测试结果沿用为新版实测结果。

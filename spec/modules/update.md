# 管理器更新规范

适用于管理器自身的 Windows x64 单 EXE。目标应用的兼容检查、补丁安装与备份恢复遵循[汉化规范](localization.md)。

## 发现与交互

- 默认查询 `txysyc/AntigravityManager` 的 GitHub Releases，选择版本号严格高于当前版本、具备对应 EXE 的最高正式 `manager-v<版本>`。草稿、预发行和其他组件的标签不参与版本比较。
- 带更新公钥的管理器默认在普通启动时检查。设置可以关闭启动检查。发现经过验证的新版时在状态栏提示，用户也可从「帮助 → 检查更新」手动检查。检查失败与已是最新版本分别提示。
- 更新窗口显示版本、发布说明、下载进度与结果。用户分别确认下载和重启。手动下载入口指向固定仓库的发布页。更新检查和下载安装均不启动常驻进程。

## 发布与信任

- 发布附件包括 `update-win-x64.json` 与其原始 Ed25519 签名 `update-win-x64.json.sig`。签名绑定版本、目标平台、文件名、大小、SHA-256 和发布说明。
- 正式构建嵌入更新公钥。客户端校验签名，再校验版本、平台、文件身份及下载内容。签名不可用、密钥不匹配或校验失败时不替换程序。未配置密钥的构建提供发布页下载入口。
- 私钥由发布维护者保管，GitHub 密钥仅传入签名步骤。自动更新与普通发行附件由同一次发布构建产生。密钥配置见[开发指南](../../docs/development.md#配置自更新签名)。

## 替换与恢复

- 更新文件留在当前 EXE 同卷的临时目录。重启前将现有 EXE 复制为短时更新进程，等待原进程退出，再检查签名、文件内容及原 EXE 指纹。相同目标路径的替换互斥。
- 同卷替换前保留旧版。更新进程保留原有启动参数，并等待新版以其声明版本完成窗口初始化。新版启动失败时用已校验备份恢复与重启旧版。恢复失败时保留备份并报告位置。
- 新版确认启动后清理该次更新的临时文件。现有设置、备份、操作记录和 Antigravity 安装目录继续沿用原路径。

# 汉化模块规范

仅约束模块 `localization`，不代表整个项目。通用边界遵循 [架构规范](../architecture.md)。

## 范围与入口

- 界面和 CLI 位于 `src/`，Go 模块位于 `src/internal/localization/`。汉化源和 Node 参考引擎位于 `engines/localization/`。
- 管理器使用内置的兼容配置、词库和注入代码构建补丁。派生的 `payload.json` 由开发工具从源文件生成，发布前检查同步。当前补丁已有已验证哈希时，构建结果必须匹配该哈希。
- 汉化概况、版本检查、备份恢复和操作记录集中于模块；可用补丁版本持续显示，已安装版本单独呈现。未完成检查时不能显示为已确认的安装状态。
- 引擎提供 `inspect`、`compare`、`install`、`restore`、`backups`。CLI 输出 JSON，失败退出码非零；面向用户的消息优先中文，原始诊断可单独保留。
- 启动时应用检查失败应保留失败提示，不得随后用备份检查成功覆盖；未识别应用时安装能力保持禁用。

## 兼容性与文件安全

- 安装资格依据应用身份、版本和原始或已知补丁 SHA-256；支持范围以 `profiles/*.json` 为准。未知版本或未知指纹不得安装旧补丁。
- 新增适配配置同时绑定已审查的语言服务 SHA-256；缺失或不同指纹不得安装。历史配置保持原验证范围。已知汉化 ASAR 的恢复资格仍由同版本原始备份决定，避免语言服务变化阻断安全恢复。
- Electron 模块一致或文案锚点匹配只构成变化报告，不能自动批准兼容性；完整页面与用户内容保护仍须单独验证。
- 安装或恢复前确认目标应用已完全退出，并取得写操作锁。原始备份按应用版本与原始指纹保存，不覆盖损坏或不匹配备份。
- 生成补丁与原始备份必须校验。替换前重新确认目标指纹，使用临时文件和原子替换；恢复只允许使用与当前版本匹配的原始备份。
- 记录保存在管理器数据目录，随统一迁移机制移动；不得仅依赖目标应用旁的备份。旧备份来源须通过同样的指纹检查。

## 翻译与语言切换

- 固定词条、服务端文案和动态句式分开维护；精确匹配已确认的 UI 文案，不对所有英文文本无差别替换。
- 保护聊天内容、代码、输入值、项目名及其他用户或第三方内容；新增规则要验证动态更新、节点复用和切回原文。
- 保留中英文切换及语言持久化；当前网页内容即时切换，原生界面下次启动生效，不修改 EXE 或语言服务二进制。
- 在常规设置用行内下拉框显示并切换当前语言，选中即生效。样式沿用 Antigravity 的主题色、圆角浮层及选中勾号。下拉框随页面挂载，不在聊天区或项目设置显示，也不使用独立弹窗。保留原生语言菜单；快捷键仅在下拉框可见时聚焦它。验证覆盖页面切换、窄窗口、键盘操作和原文还原。
- 使用 WebContentsView 承载主界面的已验证版本，语言 IPC 必须核对发送者就是主界面内容，并继续限制为回环来源的主帧。关联到同一窗口的网页访客不得调用语言设置或接收广播。
- 英文分支、翻译源键、协议字段及补丁识别标记属于功能数据，不因中文协作要求而翻译。
- 下拉菜单及 portal 弹出层只翻译显示文本与说明，不改选项值、主题预设键或回调参数。主题品牌保留原名，明暗变体可附中文标注；回归需覆盖弹出后挂载、事件值、同文用户内容保护与英文还原。

## 验证与维护

适配变更须验证未知指纹拒绝、备份完整性、重复安装、恢复、语言切换和用户内容保护。使用隔离应用与数据副本；历史词条数、测试通过或锚点数量不能当作新版本页面覆盖率。

Windows 隔离运行验证还须禁止测试副本登记 `antigravity://` 协议关联。仅在隔离样本移除这一步，正式补丁保留上游协议行为；方法见 [测试与验证](../../docs/testing.md)。

补丁版本以 `engines/localization/package.json` 为准；操作记录位于 `localization/tasks.json`，缺失时兼容读取旧根目录 `tasks.json`。命令见 [使用指南](../../docs/user-guide.md#命令行)，资源准备见 [测试与验证](../../docs/testing.md)。

## 版本与保留策略

- 管理器与汉化补丁的定版、递增及标签规则统一见 [版本与发行规范](../releases.md)。目标应用的版本和指纹仅用于确定兼容范围。
- 新引擎可继续为已验证的旧应用构建当前补丁；历史补丁不等于必须保留多套运行引擎。旧版源码标签、兼容配置、已知补丁指纹和对应原始备份持续保留，不把旧补丁直接套用到新应用。
- 参考构建输出为 `artifacts/localization/<应用版本>/<补丁版本>/`。同目录只接受字节与清单完全一致的重建，冲突必须使用新版本或独立输出目录。
- 管理器在内存生成和校验补丁，通过同目录临时文件提交替换，不额外写入补丁缓存。保留既有原始备份布局。
- 补丁携带版本身份；已知历史哈希的版本映射与当前发行哈希分开维护。未知具体版本的历史补丁不得显示为当前版本，也不能误报为未安装。
- 原始备份按应用版本与原始指纹保存，不自动清理。工作区历史发布产物可归档；仅在不再需要重装时手动清理可重建缓存，不能连带删除原始备份。

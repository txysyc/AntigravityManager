# 项目规范

本目录保存当前生效、供后续开发持续依赖的项目约定。默认使用简体中文；协作、编码、Git 与基础验证规则见 [AGENTS.md](../AGENTS.md)。

## 项目定位与全局约束

- 项目是 Windows 上按需使用的 Antigravity 模块化管理器。汉化是首个模块，后续功能通过模块扩展。
- 当前不常驻后台、不接管日常启动、不修改已有代理启动器；改变这些产品边界时需明确记录新的需求与约定。
- 桌面技术栈为 C#、.NET、WPF 与 WPF UI；汉化引擎使用 Node.js/CommonJS。版本以项目配置为准，不在规范中重复维护。
- 界面提示默认中文；品牌、文件路径、命令、协议字段及原始诊断可保留英文。失败必须先给出中文说明，原始诊断不得冒充成功信息。
- 用户数据独立于程序安装目录；操作不得静默覆盖不相关数据。模块必须遵守统一数据位置与迁移机制。

不要求每次加载全部文档。新增模块时再添加 `modules/<module-id>.md`，共同规则引用架构规范，不复制到每个模块。

## 随改动同步维护

1. 开始相关改动前，读取适用规范，区分已确认约束、现有实现和待实现需求。
2. 改动影响产品边界、目录结构、模块契约、持久化行为或验收要求时，在同一批改动中直接同步相应规范和入口链接，无需等待额外的文档更新指令。
3. 小修复、文案调整或内部实现变化未改变约定时，不为制造更新记录而改写规范。版本号、指纹、字段定义引用实际配置或源码位置。
4. 完成前检查实现、规范和验证结果是否一致。发现冲突时说明差异；不得为了让检查通过而静默放宽已确认约束。尚未完成的需求标为草案，不能写成已有能力。

这里的“自动更新”指开发协作者随任务主动同步；没有后台文档生成器。`npm run check:guidelines` 检查链接、版本和部分中文提示，不能替代语义审查或自动判断规范是否完整。

## 较大变更

新增模块、修改数据格式或调整兼容策略等较大变更，可按需建立 `changes/<feature-name>.md`；小改动无需创建。单个文件包含“目标与范围、行为与约束、验收标准、实现计划、验证结果”，并标明草案、实施中或已完成。完成后将长期约定同步回对应规范，原文件保留结果；不强制增加多份计划、任务或决策文档。

`docs/` 保留操作指南，`docs/reports/` 与 `analysis/` 保留历史分析和证据，它们不能自动批准新版本兼容性。

# 架构与模块规范

适用于整个管理器及后续模块。产品定位见 [规范索引](README.md)，汉化专属约束见 [汉化模块规范](modules/localization.md)。

| 位置 | 职责 |
| --- | --- |
| `src/` | Windows 入口、MyGo 原生 UI 与 CLI |
| `src/internal/localization/` | ASAR 构建、兼容检查和汉化维护 |
| `src/internal/storage/` | 数据定位、设置、锁与迁移 |
| `engines/<module-id>/` | 开发资源、参考引擎与独立检查 |
| `assets/branding/` | 品牌资源，窗口图标使用内嵌 PNG |
| `scripts/` | 启动、打包和生成发行说明 |
| `tools/` | 分析工具、样本准备和验证 |
| `analysis/` | 历史适配摘要和证据；本地提取物不入库 |
| `output/` | 默认的发行成品目录 |
| `artifacts/` | 本地缓存、临时构建、样本和验证结果 |

## 模块与界面

- 壳层在入口显式接入功能，直接调用 Go 模块。模块不得依赖彼此的内部实现；仅共享有实际共同需求的能力。
- 界面区分管理器、目标应用、可用补丁与已安装补丁版本。安装和恢复能力分别由引擎判断。
- 明暗主题覆盖各页。任务期间显示进度和结果，防止冲突操作或关闭窗口；写事务开始后允许其完成。
- CLI 标准输出承载 JSON 结果，失败返回非零退出码。许可文本由独立的 `notices` 操作输出。

## 数据与迁移

- 默认数据目录为 `%LOCALAPPDATA%/AntigravityManager`。固定引导位置的 `location.json` 保存当前路径；配置位置不可用时明确报错。GUI 和未显式传入 `--data-dir` 的 CLI 使用同一位置。
- 设置、定位文件、操作记录和原始备份兼容既有布局。模块数据随管理器迁移。迁移拒绝非空目标、相互包含及重解析点；逐文件复制、校验后切换，保留原目录。失败不切换位置或覆盖目标数据。
- 数据迁移与维护任务互斥。其他实例发现数据位置变化后不得继续写旧位置。不自动删除可能仍有效的操作锁。
- 隔离验证必须显式使用测试数据目录。不可用的备份、权限不足或校验失败应明确失败。

## 资源与发布

- Windows x64 EXE 内嵌资源与实际依赖许可；无外部管理器运行时。发布脚本发现资源版本不一致或缺少许可时失败；第三方许可原文不翻译或改写。
- `output/` 保存可分发的 EXE 和独立 SHA-256 文件，不覆盖旧产物。`artifacts/localization/` 保存参考补丁，`artifacts/fixtures/` 保存测试基线；二者不随程序分发。
- 已结束的验证可以校验后归档。工作区整理不得删除原始备份、正在使用的数据或报告引用的证据，也不得跨目录链接递归处理。
